Verteilerly — Documentation

Documentation for telecommunications distribution frames in LSA+ technology: cover sheet, frame layout and strip sheets from one data model instead of copied spreadsheets. This page describes every function of the program in the order in which you meet it at work.

1   Overview

A distribution frame consists of bays, a bay of strips, a strip of pins, a pin of the two wires a and b. Two wires together are one pair (DA). Across them lie the cables: a cable takes up a contiguous block of pairs, if need be across several strips. A jumper connects two wires inside the frame and is kept at both ends.

Everything is in one project file. Three kinds of sheet come out of it:

SheetWhat is on it
Cover sheetTitle, frame, structure, key figures and the project data as a list. It carries no title block — it is one itself.
Frame layoutEvery strip as a row of pairs, the cables as blocks in it. Two bays share one sheet and lie crosswise; a single bay stands upright. Each bay gets a sheet of its own as soon as the frame has more than two bays or one bay carries more than thirteen strips.
Strip sheetOne per strip: pin, wire, color, designation, jumper, remark and the cable column.

Preview, PDF and Excel workbook draw the same sheet model — what is in the preview is in the print as well.

2   Creating and saving a frame

File ▸ New frame… (Ctrl+N). The dialog has two halves: on the left the frame, on the right the project data.

  • Frame name and frame number — they stand in the title block of every sheet and can be changed later under Edit ▸ Project data.
  • Sheet template — which sheet layout is to apply; changeable later. The choice also decides which project-data fields stand on the right: shown is what the title block of that template carries. A template without an installation number therefore leaves the field out — change the template and the list changes. The document title is always there: it names the PDF and heads the cover sheet, so it hangs on no title block. A field that is left out keeps a value from the defaults but is deselected — it appears on no sheet until it is ticked again under Edit ▸ Project data.
  • From template — the supplied structures and the ones you stored yourself are in the drop-down menu.
  • Custom — bays, strips per bay and pairs per strip. There, 8, 10 and 20 pairs are offered; any other number is typed in under Custom. Underneath, the result is shown as you go: 4 strips, 40 pairs. A checkbox stores the measurements as a template right away.
  • Advanced frames: set up each bay separately — the checkbox puts a table with one row per bay in place of the two numbers: how many strips it carries and how large they are. This is how an unevenly equipped frame is built — one bay with two 20-pair strips next to two bays with ten 10-pair strips. One strip size per bay. Such a frame can be stored as a template as well — the file then carries one row per bay.
  • Letters instead of numbers — the check mark below the custom frame gives the strips letters: strip A instead of strip 1. It applies to both ways — a template says how many strips there are, not what they are called. It starts empty — every new frame is counted at first — and later it can be changed under Settings ▸ Label the strips (section 3).
  • Reverse the frame layout — the check mark below it puts the pairs on the frame layout from right to left, for a frame that is filled from the right. Like the other one it applies to both ways and can be changed later under Settings ▸ Reverse the frame layout (section 3).
  • Project data — company, customer, author and so on. Whatever is kept in the defaults is already filled in. Next to every date field — drawn on, created on, as of, checked on — stands a button Today that enters today's date there and ticks the field. One per field: created and checked are rarely the same day. The same buttons stand under Edit ▸ Project data; in the defaults for new frames they are missing on purpose — a date left standing there would be the day before yesterday's in the next frame.

A structure built like this can be stored as a template: in the dialog itself or later through Edit ▸ Save as template…. It becomes a YAML file in the working folder and appears in the menu at once.

Saving is done with Ctrl+S as .vtly — readable JSON with a format version; older versions are still read. When you close with unsaved changes the program asks; the buttons are Save, Discard and Cancel. Older files are called .vtly.json; they can still be opened, and saving them keeps their name.

Opening read-only — File ▸ Open read-only… (Ctrl+Shift+O) shows a file for looking at: nothing can be changed. No cell takes an entry, Del empties none, alignment, bold, italic and the split cell are off, in the frame overview no double click terminates a cable and no dragging moves one, and the menu entries that work on the frame are greyed out — Terminate cable, Change, Remove, Project data, Label strips, Reverse frame layout, Undo and Redo. Reading, selecting, searching, paging and output stay: PDF, Excel workbook and CSV work as always, and Save as… creates a file of your own — that one is ordinary again. The same happens by itself when the file is write-protected on disk — otherwise you would notice only at saving time, with the work behind you. How to tell: the title bar says (read-only), and in the strip view a red read-only stands next to the percentage of the split cell.

Double click in the file manager — a project file (.vtly) opens Verteilerly as soon as it is linked with the right executable in the file manager. On Windows Verteilerly enters this itself on request; on Linux it is done in the file manager: right-click a project file ▸ Open with ▸ Other application. The command line works too: Verteilerly <file>.

Tools ▸ Link project files… says how things stand and, on Windows, offers the two buttons for it:

  • which file is to be linked — with the PortableApps edition the VerteilerlyPortable.exe, not the program in App\Verteilerly: the launcher sets up folders and environment and only then calls the program. As an AppImage the image file itself, not the mount point under /tmp, which disappears when the program ends;
  • whether they are linked — and if not, which program currently opens the project files. What counts is what the file manager does: on Windows the user's own choice comes first (FileExts\.vtly\UserChoice, set by „Open with ▸ Always"), on Linux the mimeapps.list including removed associations;
  • how to set it — on Windows with Link now or Remove the link right there.

The link survives an update. What is registered is the file named above — with the PortableApps edition the launcher, which keeps its name and its place while the program behind it is replaced. Writing happens under HKEY_CURRENT_USER only: that needs no elevated rights and applies to whoever asks for it.

It is checked at every start. If the program is moved or renamed, the entry points nowhere; the dialog then calls it outdated and offers Renew the link, and the status bar says so at startup. The same goes for another program having taken over the project files.

The plain .exe carries its version in its name (Verteilerly_2026.10.13.exe) — an update is a different file there, and the entry still points at the old one. If the registered file is gone at startup, Verteilerly carries the link over to the running version silently and says so in the status bar. If the old file is still there, two editions stand side by side — one on the stick, one in the downloads folder — and then it is only reported: otherwise the copy started last would quietly take the link for itself. Renew the link settles it either way.

The user's own choice stays untouched. Where someone on Windows has already chosen “Open with ▸ Always use this app”, that choice still wins — it lives under FileExts\.vtly\UserChoice and cannot be set from outside, not even by us. Our entries are then the basis on which Open with offers Verteilerly at all.

3   The editor

On the left the frame overview: every strip a box of pair cells, bays side by side, the cables as blocks. A click selects a pair, a double click terminates a cable or opens an existing one. A click on a cable jumps to its start in the strip view — to the designation of its first pair on that strip, whichever of its cells was clicked; if the cable runs across several strips, the clicked one counts. From there you can type straight away. A click on a free pair still only switches the strip. The cells are larger here than on the sheet, so that even a cable over a single pair shows its name: it wraps as long as the lines fit into the block, and is only cut off when even that is not enough.

How the strips are named — Settings ▸ Label the strips switches between 1, 2, 3 and A, B, C. Inside they are still counted from 1; the letter is only another name for the same strip — the 27th is then called AA. The choice applies wherever a strip is named: in the chooser, on the sheets, in the frame layout, in the PDF, in the Excel workbook and in the data lists — and in the jumpers, because they point at the same strips. Both may be typed: whoever enters C 2a means the third strip, and 3 2a means it too; in the project file the addresses are numbers anyway.

It belongs to the frame, not to the program: its strips carry those labels on the hardware, and so the choice is kept in the project file. A frame with letters and one with numbers can be kept side by side — each brings its own labelling. It is not remembered: every new frame starts counted and gets its labelling in the New frame dialog or here — just like the reversed layout. The menu is greyed out as long as no frame is open.

From right to left — Settings ▸ Reverse the frame layout turns the reading direction of the frame layout: the pairs then run from right to left, like a frame that is filled from the right. Only the picture of that sheet is turned — in the preview, in the PDF and in the Excel workbook alike. Pair 1 stays pair 1: pin and pair keep their numbers, strip sheets, data lists and addresses (1 1a) are untouched, and the cable blocks keep their width. This too belongs to the frame and is kept in the project file; the tick can be taken back with Undo. The preview jumps to the frame layout while doing so — that is where the change shows; with the next keystroke it goes back to the sheet of the strip being edited.

On the right the strip view of the chosen strip with the columns pin, color, designation, jumper (two fields), remark and cable. Color, designation, jumper, remark and the cable label can be changed; pin, wire and cable position are fixed.

The layout adapts to long names — Settings ▸ Fit the layout to long names. A cable name that does not fit into its block wraps; where even that is not enough, the cells of the frame layout grow until it fits on two lines (at most to two and a half times — a long name on a single pair should not blow up the frame). Turned off, the layout keeps its usual grid and a name that is too long is shortened as before. The sheet is untouched by this: there the sheet template decides.

The cable column shows the whole name. The label stands in one cell across the entire cable block — as tall as the cable has pairs — and it wraps instead of ending in an ellipsis after a few characters. Wrapping happens at word boundaries; only a single word that is wider than the column anyway breaks in the middle. Typing still happens in that same cell.

Undo — the two arrows ↶ and ↷ next to the strip selector take back the last change to the frame and bring it back again; so do Edit ▸ Undo (Ctrl+Z) and Redo (Ctrl+Y). The last 50 steps are kept — every change to the frame, from a typed character through a terminated cable to the labelling of the strips. The chosen strip stays where it was. Settings of the program are not taken back: sheet template, theme and defaults do not belong to the project. Who changes something new after taking a step back can no longer bring it forward — the other path has been taken. And with a new or an opened project the row starts over.

Text options — next to the strip selector are five buttons: align left, center, align right, as well as F for bold and K for italic. They act on the selected cell and show what applies there. Pressing an alignment again takes it back — then what the sheet template holds for that column applies again.

Several cells at once: select several cells — drag across the column with the mouse button held down, or click single ones with Ctrl — and every press of a button applies to all of them. Splitting and the percentage too. All of them get the same thing, not each its own opposite; which way it goes is decided by the cell the cursor is on. Whatever in the selection cannot be styled stays untouched.

Styleable are color, designation, jumper and remark; for pin, wire and cable the buttons are off. The two jumper fields belong to one cell of the sheet and therefore carry the same style. The style belongs to the frame, is kept in the project file and applies on the sheet, in the PDF and in the Excel workbook as well.

Splitting a cell — the button with the divided box turns a cell into two labeling fields side by side; the percentage field next to it says how wide the right one is (10 to 90 %). Editing then happens in two input fields — Tab jumps from the left one into the right one, Esc discards. Switching between the halves does not leave the cell, and a click somewhere else takes nothing with it: what was typed stays. On the sheet there is no line between the two: there it looks like one cell holding two entries. In the strip view a fine dotted line hints that there are two fields.

Splittable are designation and remark; for color and jumper the button is off. If the split is undone, the text of the right field is kept and merely appears nowhere any more. In Excel and CSV both entries stand one after the other in one cell — a grid has no half column.

Searching. Edit ▸ Search… (Ctrl+F) searches the whole frame: color, designation, jumper field — targets in the chosen notation and notes —, remark, the labels of the cables as well as the project data including own fields and the frame name. The second text of a split cell counts as well. The search runs as you type, from the second character on; upper and lower case make no difference.

The list names for every match where it lies (bay, strip, pin), which field it is and what stands in it. A double click, Enter or Go there switches to the strip and puts the cursor on the cell; the status bar at the bottom repeats what was found. Matches in the project data open the Project data dialog instead — that is where they are. The word searched for last is back in the field the next time.

Del clears the selected cells without opening them first — several at once as well. What is deleted is the content, not the form: a split cell loses both texts and stays split, a cable cell loses its label, not the cable. For pin and wire the key does nothing, and while editing it deletes characters as usual.

Enter closes the entry and goes one row down — as in a spreadsheet: a column is filled from top to bottom without having to press the down arrow every time as well. The next keystroke opens the field there by itself. Even without an entry Enter goes one row down: whoever only looks through a column gets from row to row the same way, and a row with nothing to change is simply skipped. In the last row the cursor stays. If an entry was not accepted — an unreadable jumper, say — it stays as well: there is something to put right.

Cut, copy, paste — a right click in the table opens the menu for it; the usual shortcuts Ctrl+X, Ctrl+C and Ctrl+V do the same as long as no field is open for typing (there they belong to the text). What is copied is the block from the topmost left to the bottommost right selected cell — including what lies between, so that what is pasted stands in the same columns again. Pasting goes from the cursor downwards and to the right; cells that cannot be written — pin, wire, a cable column without a cable — stay as they are. The format is that of a spreadsheet, so a column can be carried to Excel and back. One paste is one step to undo, even if it fills twenty cells.

A split cell comes along whole: both fields and the width of the right one. What was copied is what is pasted — if the copied cell was not split, the target cell is not either afterwards. Outwards, that is on the clipboard for other programs, both fields stand one after the other (Melder EG 12), just as in CSV and the Excel workbook: a grid knows no half column. Text that comes from outside says nothing about the split — it then stays as it was at the target.

Out of a split cell it goes straight down as well — out of the right field too. If the cell below is split as well, the cursor lands in its right field again: a column of extensions can be typed from top to bottom without clicking in between. If it is not split, only the cursor moves on.

The strip is chosen from the drop-down menu or stepped through with the two arrows next to it (Alt+← and Alt+→); at the first and the last entry the respective arrow is off.

Under the menu bar lies the toolbar with what is needed most often: new frame, open, save, export, terminate, edit and remove a cable, and the view button.

The export button has two parts: on the left it says Export (PDF) — a press writes the format in brackets —, on the right an arrow. It opens the same menu as File ▸ Export: As PDF…, As Excel workbook… and As CSV…. Whatever you choose there is on the button afterwards and stays after a restart — whoever always needs CSV presses nothing but the button from then on. Ctrl+E still writes a PDF.

The view button works like the export button: it says which area a press shows and hides — at first Show preview —, and it stays pressed while that area is visible. The arrow on the right opens the three areas of the window: frame overview, strip view and preview, each with a check mark while it is visible. A click on an entry shows or hides the area at once and puts it on the button — every further press then applies to it. The choice stays after a restart. F7, F8 and F9 switch independently of it.

View ▸ Show preview (F9) shows and hides the sheet preview. View ▸ Show frame overview (F7) and View ▸ Show strip view (F8) do the same for the other two areas: whoever only types gives the strip view the full height, whoever only wants to see the sheet gives the preview the whole window. All three switches are after a restart as they were left. The splitter between input and preview lets no side disappear: it moves only down to the narrowest width both still need. Whoever really wants to be rid of an area uses the switch made for it. View ▸ Dark appearance (Ctrl+D) switches the color set. The sheet stays untouched by it: paper is white. The arrows in the file and export dialogs — back, forward, one level up — follow the appearance as well; the program draws them itself, because Qt's own images would hardly be visible in the dark set.

The preview shows the finished sheet as it would come out of the printer — the same drawing the PDF is made from. At the top the sheet is chosen: drop-down menu, two arrows and a counter (3 of 6). Underneath stands which sheet template applies; it is changed under Settings ▸ Sheet template. Every entry shows up immediately — what is here is in the print as well.

Enlarging — the same everywhere: −, a chooser and +, plus Ctrl and the mouse wheel. The bar for it stands above the frame layout, at the right of the header of the strip view and above the preview. In the frame layout the cells and their labels grow with it; in the strip view the type and the row height. What no longer fits the window is scrolled. The preview additionally knows fit to window, because it shows a whole sheet:

Enlarging — at the right of the same row stand −, a chooser and +. Fit to window puts the whole sheet into the window, which is how the preview starts; the steps from 50 % to 400 % show it at its true size and beyond — at 100 % one millimetre of the sheet is one millimetre on screen. Ctrl and the mouse wheel do the same. Once the sheet no longer fits the window, scroll bars appear; without Ctrl the wheel only scrolls. The chosen size stays when the sheet is changed.

4   Cables

Cutting, copying and pasting a line — in the frame overview a right click on a cable opens the menu: Cut line, Copy line, Paste line. It is pasted where the right click was. Copying lays a second cable of the same kind — with its wires, but without the jumpers, since a connection exists exactly once; it can be pasted several times. Cutting does not take the cable away at once: it stays and moves on pasting — with wires and jumpers. Removing it and laying it anew later would lose them. If it does not fit at the target or something lies there already, the status bar says so and it stays where it is. Dragging with the mouse does the same, by the way (with Ctrl: copy).

Terminating remaining lines — what a shortened line does not yet have terminated is its rest. Two ways terminate it: Edit ▸ Terminate remaining lines… takes on all shortened lines of the frame at once, the right-click menu in the frame overview terminates one line at exactly the place clicked.

The collective dialog shows for each line what is terminated, and where its rest goes is your choice — strip and from pair can be changed in every row.

Preset is a proposal: first the place directly behind the line — that is where its continuation belongs, and it then grows into that section instead of beside it —, otherwise the first free run that carries the rest completely. No rest is split up: a strand scattered across three strips can no longer be followed on the sheet.

The column Room says for each row where you stand: 2 pairs free (with the addition continuation when the place adjoins directly), occupied when something lies there already, or strip too short when the strip ends before. The rows are checked from top to bottom, each against those above it — if two point at the same place, the upper one gets it and the lower says occupied. Whoever does not want to terminate a line at all takes out its tick; it then stays shortened. Lines for which nothing free could be found start without a tick — they too may be given a place by hand.

The short way leads through the right-click menu: its submenu Terminate remaining line lists the shortened lines — each entry with the name and how many pairs are left over — and terminates the line clicked where the right click was, without a dialog. What does not fit that place completely is not left out but stands there greyed out with the addition does not fit here — otherwise one puzzles over where a line has gone. If the place adjoins the line directly, it grows into its section here too instead of beside it.

The wire colours come along: the new pairs continue the cable type's sequence, what was entered by hand stays. Both ways are one step to undo. If no line is shortened or the frame is open read-only, the menu entry and the submenu are greyed out.

Terminating — Edit ▸ Terminate cable… (Ctrl+K) or a double click on a free pair. Label, cable type and size are to be given; strip and from pin come from the selection. Preset are 2 pairs and J-Y(St)Y — the most common cable in the field; both can be changed in the dialog. Of that, terminate follows the cable size — the normal case is that a cable is terminated completely; whoever wants to shorten it sets the number down afterwards, and a note says how many pairs stay unterminated.

Editing — a double click on a terminated cable or Edit ▸ Edit cable… (Ctrl+Shift+E). Label, cable type, size and length can be changed, and the dialog carries the button for removing it as well.

Relocating — a terminated cable can be dragged to another place with the mouse in the frame overview. It takes along everything that belongs to it: wire colors, designations, remarks, notes, text styles — and the jumpers, because they point at the wire, not at the place. What is grabbed is the pair under the pointer: exactly that one lands at the new place when you let go. A frame shows where the cable would land; where there is no room it is dashed, and the cable stays where it is. A cable in several sections becomes one again when relocated — the new place must therefore hold all of it.

Holding Ctrl while dragging copies instead of moving: the second cable is called … (copy) and gets the type, the size and the same wires with their texts. The jumpers do not come along — a connection exists exactly once, not twice.

Larger and smaller — Of that, terminate can be set here just as when terminating: the cable grows and shrinks at the end, the start stays where it is. What becomes free is free again, including the wire colors the program put there. If the strip is not enough, the same overflow dialog asks as when terminating; if another cable is in the way, this is reported and nothing is changed. Strip and from pin are fixed — for a different position take the cable off and terminate it anew.

The label can also be overwritten directly in the cable column of the strip view — where it stands. That holds for a cable created without a label as well.

Removing — Edit ▸ Remove cable (Ctrl+Shift+K), after selecting a pair with a cable. The toolbar carries the same button with an arrow: a press takes the whole line off, the arrow opens both ways — just like the export button. In the right-click menu of the frame overview the submenu is called Remove line and lists the same two entries; there it always means the place clicked, not the previous selection.

If a line lies in several sections — after an overflow onto the next strip, for instance — Remove only this section stands beside it: then only the piece holding the selected pair comes off, and the entry names it by its place (strip 2, pairs 1–3). The line stays terminated and is shortened afterwards — what came off is its rest and can be terminated again with Terminate remaining lines, elsewhere as well. Its nominal size does not change.

The last section cannot be taken off on its own: a line without a pair would be none — then it is removed completely. If a line lies in one piece, the entry stands there greyed out with the reason. The section's wire colours come off with its pairs; those of the other sections stay, and so does anything entered by hand. Either way it is one step to undo.

Overflow — if a cable does not fit onto the strip completely, a dialog asks what is to happen with the rest: continue on another strip (with strip and starting point) or let it lapse. A continued cable stays one cable with several sections.

Shortened — if a cable is terminated with fewer pairs than it has, (shortened) stands behind its name; the strip sheet adds shortened: 4 of 6 pairs. That way the sheet shows that wires are left over.

Settings ▸ Show shortening at the cable turns that addition off. Then only the name stands in the cable column and on the frame layout, and the whole block belongs to it. At the cable itself nothing changes; that it is shortened stays visible in the file, in the data lists and in the overview. The setting belongs to the program, not to the frame — it is kept in Verteilerly.conf and applies to every project that is opened.

Wire colors — the cable type fills the color column by itself: J-Y(St)Y and the VDE color code for telecommunications cables layer by layer, star quads in pairs, DIN 47100 as a list. The cable types are YAML files in the working folder and can be extended.

The color sequence belongs to the cable: if cable type or size changes, the colors follow, and if the cable is taken off, they go with it — the next line has a sequence of its own. The yardstick is what the program set: as long as exactly that still stands in a cell, it changes it again. What you entered by hand stays; only the checkbox Also replace wire colors changed by hand in the edit dialog overwrites that as well.

5   Jumpers

Every wire has two jumper fields side by side — one per jumper, with a heading above them. The target is entered as an address of strip, pin and wire:

NotationExample
without a prefix1 1a
with a hyphen1-1a
with L before the stripL1 1a
with L and a hyphenL1-1a

Which of them is shown is set under Settings ▸ Notation of the jumpers. Everything is always read: any form may be typed, no matter which one is set, and in the project file the address stands unchanged as 1 1a. Whoever switches has to touch neither their projects nor their habits.

The counterpart enters itself: a jumper is one object that is kept at both ends. Whoever types both targets into one field (3 2a  5 4a) gets them distributed over both fields. On the sheet they stand side by side in one cell — there it should not show that these are two fields.

Checked while being entered: a jumper onto itself, a target that does not exist in the frame, the same counterpart twice or a third jumper on the same wire are refused — the message stands in the status bar, and what was there stays untouched. So what does not go through is not half taken over either.

A note instead of a target — the templates. Not every wire leads to another one: one goes straight on, one is faulty, one carries the end-of-line resistor. For that the jumper field knows templates — supplied are direkt, defekt and 12k. A right click on a jumper field opens the submenu Templates; one press enters the template. Typing works as well, and case does not matter.

Everything else that cannot be read as a target stays a mistake — and the message names the templates. That is the point of the list: a mistyped target should be noticed instead of quietly becoming a note. A note takes up one of the two fields, stays in it and is not mirrored — it belongs to the wire. What can be read as a target stays a target.

Older frames keep their notes. Up to 2026.10.07b3 the jumper field accepted any free text. Such notes are kept in full — they are loaded, displayed, printed and saved again, and they can also be confirmed unchanged even though they are in no template. Only new text has to be a template. On opening, the status bar says which notes of the frame no template knows (“1 note is not among the templates: …”); whoever still needs them adds them to the list.

Changing the list — Settings ▸ Templates for the jumper field…, or Edit templates… in the same submenu. One template per line; empty and duplicate lines are dropped on accepting. The list belongs to the program, not to the frame: it is kept in Verteilerly.conf and applies to every project.

6   Project data

Edit ▸ Project data… (Ctrl+B). What is here appears in the title block of every sheet.

Shown are the fields of the sheet template in use — the same selection as in the New frame dialog: what its title block does not carry is not offered for entry here. The document title is always there. Unlike when creating a frame, nothing is deselected: a field that this template does not carry keeps its content and its check mark as they were — another sheet template (Settings ▸ Sheet template) shows it again.

Frame name and number stand at the top. They cannot be deselected — a sheet without a frame name would be none.

Every field has a check mark. A deselected field disappears from the sheet together with its label — a row „customer" without a customer would be worse than none at all — and keeps its content: whoever wants to leave out the installation number for this print only does not have to delete it. All and None set every check mark at once.

These fields exist:

Company and customer carry an address, not a line: both fields are multi-line, name, street and town stand one below the other on the sheet, the label only at the first line.

Own fields are freely named rows such as Location: basement. Which ones exist is set in the sheet template — they are created and named in the sheet template editor; here they are filled in: the name is fixed, the content belongs to the frame. The check mark in front decides, as with the other fields, whether the row appears on the sheets; the content is kept either way. A field of the template without content stands on the sheet as an empty row — to be filled in by hand, on the cover sheet as well, where empty project-data fields are otherwise left out. Every field stands on every sheet in the same place, where the template put it into the block; the row strip falls away on the frame layout, because that sheet shows every strip. If another sheet template does not carry a field, its content stays stored and comes back with that template.

Changing the wording — the switch Advanced: change the wording on the sheet in the selection row folds out a list next to the fields: on the left the default word, on the right your own. Where customer stands, client may stand. Only the word is changed — content, check marks and order stay — and it applies on all sheets and in the Excel workbook. Reset to default writes the default word back everywhere. Only what differs is kept.

Defaults for new frames — Settings ▸ Defaults for new frames… carries the same fields and writes them into the Verteilerly.conf; a button takes them over from the open frame. When a frame is created they are already filled in; checked is only what they fill. Edited project data do not change the defaults by themselves — otherwise the last customer would overwrite them unasked. An open frame stays untouched: there, what is in the file applies.

On small screens — no dialog grows larger than the screen it opens on; if it stands partly beside it, it moves fully onto it. If the fields do not fit one below the other, a scroll bar appears: the content scrolls, Apply and Cancel stay firmly underneath. If there is room enough, nothing of the scroll bar is to be seen.

Moving dialogs aside — every dialog can be dragged freely by its title bar, questions, messages and file dialogs included. That keeps the main window underneath readable, for instance the strip values are being copied from. The dialog opens centred over the main window and stays in front of it; while it is open, the main window waits for it.

7   Sheet templates

How the sheet looks is said by a sheet template; what is on it comes from the project. Three are supplied:

TemplateWhat for
StandardAll columns, narrow cable column with a turned name.
Knapp (sparse)A pure jumper sheet without designation and remark, cable column wide and horizontal.
Ausführlich (detailed)Large type, high rows, one bay per sheet.

The title block can also be built differently: with schriftfeld_art: beispiel the matrix of date and name with created, revised and checked stands top left, frame, number and strip bottom left, and two boxes with the addresses of company and customer on the right. No ready-made template for it is supplied — the arrangement is open to any sheet template of your own. Whoever has already made such a template has it in their working folder; it stays where it is.

It is chosen when a frame is created and later under Settings ▸ Sheet template… (Ctrl+Shift+B). The choice belongs to the workplace, not to the single frame: it is kept in the Verteilerly.conf and applies to preview, PDF and Excel workbook.

Renaming — in the same dialog a button gives the chosen template a different name: Knapp does not say the same to everyone, Jumper sheet hall does. Only the name is changed, not the identifier — that is the file name and stands in the Verteilerly.conf. It is written into the working folder; if it was a supplied template, a copy with the new name is created there, and everything else in it stays as it is — comments included.

Deleting — the same dialog also takes a sheet template away, after a confirmation and a supplied one as well: whoever never uses it should not have it in the list. Deleted supplied sheet templates stay deleted, even after a restart; the button Restore supplied templates brings them back exactly as they were delivered — changed ones included. Your own stay untouched by it. The built-in standard template remains available in any case, even when its file is gone.

7.1   Writing a sheet template of your own

A sheet template is a YAML file in the subfolder blattvorlagen/ of the working folder:

  • Windows: <program folder>\daten\blattvorlagen\
  • Linux: ~/.config/Verteilerly/blattvorlagen/

The file name is the identifier: the file for id: eng is called eng.yaml. Only then do rename and delete find it again. It is read at startup — a new file is offered after a restart. The keys stay German, they are the format of the file.

Two lines are required, id and name. Everything else is optional: what is missing comes from the built-in default. A template therefore states only what it wants differently:

id: eng
name: "Eng"
rand: 8
zeilenhoehe_max: 7
spalten: [stift, ader, farbe, rangierung]

A typo? The program says so at startup. A faulty file does not take the others with it — it is skipped, the remaining templates stay available. And a key it does not know is remarked upon instead of being passed over in silence: zeilenhohe_max would otherwise do nothing and nobody would know why. The template still applies — it may come from a newer version of the program. The same goes for frame templates and cable types.

The sheet as a whole

KeyMeaningDefault
idRequired. Identifier and file name at once; it is kept in the Verteilerly.conf.—
nameRequired. How the template is called in the menu.—
beschreibungA sentence about it, shown in the template dialog below the list.empty
standardtrue makes it the preselection for new frames.false
randSheet margin all round in mm.12
schriftfeld_hoeheHeight of the title block at the foot of the sheet in mm. Two addresses need more.26
kopfzeile_hoeheHeight of the heading row of the strip sheet in mm.7

buchten_je_blattHow many bays the frame layout puts side by side; at least 1.2

kabel_gedrehttrue turns the cable name in the strip sheet sideways — for narrow cable columns. true
zeilen_kabelOnto how many lines the cable name in the cable column may wrap at most; below that the type gets smaller. On the frame layout the limit does not apply.2

The font sizes stand in points under schrift: gross (20) for the cover sheet, mittel (11) for headings and cable names, normal (8.5) for the table, klein (7) for labels. In addition there is leiste for the label Leiste 1, Leiste 2 … to the left of each strip on the frame layout: 0 (the default) means like the others — then klein applies, and normal on a strongly enlarged layout. A number there fixes the size without touching the other types.

The columns of the strip sheet

spalten is a list in the order in which they stand on the sheet. The short form is the bare field name; the long one takes a heading, a width and an alignment:

spalten:
  - {feld: stift,       ueberschrift: "Stift",  anteil: 10, ausrichtung: mitte}
  - {feld: ader,        ueberschrift: "",       anteil: 7,  ausrichtung: mitte}
  - {feld: bezeichnung, ueberschrift: "Was",    anteil: 46}
  - bemerkung

Available are stift (pin), ader (wire), farbe (color), bezeichnung (designation), rangierung (jumper), bemerkung (remark) and kabel (cable) — any other name is rejected. ausrichtung is links, mitte or rechts. The anteil is not a millimetre figure but a ratio: all shares together are stretched to the sheet width, so the template stays usable when the margin changes. A column without a heading of its own belongs to the previous one — that is how Stift stands above the number and above a/b.

The title block

schriftfeld is a list of blocks, each block a list of marks; the blocks stand side by side:

schriftfeld:
  - [verteiler, verteilernummer, leiste]
  - [erstellt, stand, geprueft]
  - [firma, kunde]

Marks are firma, kunde, anlagennummer, kundennummer, verteiler, verteilernummer, leiste, blatt, erstellt, stand, geprueft, gezeichnet, dokumenttitel and strich — plus the name of every own field of this template: an own field stands there with its name (- Auftrag) and thus belongs to exactly one block, so several fields can be distributed independently of each other. strich is a horizontal rule across the block: not an entry but a line that separates what stands above it. It runs edge to edge — flush with the border of the title block, or with the dividing line to the next block, leaving no gap at the sides. In the PDF it is a fine line, in the Excel workbook the bottom border of the row; in the plain data lists it does not appear. Deselected project data disappear together with their label, and on the frame layout leiste falls away: that sheet shows all of them.

The short form is the bare mark. Written out, an entry brings its own ausrichtung — links (the default), mitte or rechts. It applies to the value, not to the label: that one stands at the left edge of its block and keeps the rows lined up. Drawn sheet and Excel workbook both follow it.

schriftfeld:
  - [firma, kunde]
  - - verteiler
    - {marke: verteilernummer, ausrichtung: rechts}
    - strich
    - {marke: blatt, ausrichtung: mitte}

eigene_felder is the list of the own rows — the names only. Each name is then a mark of the title block: wherever it stands in a block, the row stands. They are filled in per frame under Edit ▸ Project data. eigene_felder_auf says on which kinds of sheet they appear (deckblatt, belegung, leisten); without the key on all of them, an empty list means: on none.

eigene_felder:
    - Auftrag
    - Monteur
eigene_felder_auf: [leisten]
schriftfeld:
    - [firma, kunde, Auftrag]
    - [verteiler, verteilernummer, leiste]
    - [erstellt, stand, Monteur]

The mark eigene for all fields existed until 2026.09.30. If it is still in a file, it is skipped with a remark — enter the fields one by one.

schriftfeld_anteile gives the widths of the blocks as a ratio ([0.42, 0.58]); without it the program divides them by eye. schriftfeld_art is standard (label and value in columns) or beispiel (matrix, frame and two addresses as described above).

The measures of the frame layout

leistenlabelWidth of the column in which Leiste 1 stands.14

A complete example

  - {feld: kabel,      ueberschrift: "Kabel",      anteil: 20}

The file goes into the folder above as halle.yaml; after the next start Rangierblatt Halle stands under Settings ▸ Sheet template…. The preview shows at once what the numbers do — try, look, improve.

Check it first: Tools ▸ Check sheet template… reads the file wherever it lies and says whether the program accepts it and what it has read in it (section 10).

8   What applies on the sheets

  • No heading above the table — which strip a sheet shows is said by the title block; the table starts at the margin and has the room.
  • Pin stands above the number and above a and b: a column without a heading of its own belongs to the previous one.
  • No text runs beyond its field. If a designation, a remark or a cable name does not fit, the type is made smaller for that field only — down to 5 pt; below that it is shortened and an „…" shows that something follows.
  • The frame layout fills the sheet: the boxes grow as far as the page allows, and what is left over is distributed as air between the bays and the strips — no empty strip at the margin. The labels of the strips stand at the left edge of the sheet, in line with the heading and the title block below it.
  • In the frame layout there is no grid: only the cable is drawn, free areas stay unbroken. No supplied template carries pair numbers; whoever wants them sets da_nummern: true. In the editor every strip stays divided — that is where you click.
  • The cable name stands in the middle of its block, horizontally as well as vertically, and as large as the block carries it — with air all round, so that a small block does not look crammed. When it gets tight the name is wrapped first and only then made smaller: two lines at full size read better than one shrunken one. How many lines it takes is up to the block: no limit applies here. It wraps at spaces and at the characters that structure a cable name anyway (/, -, _). If that does not suffice either, the word is hyphenated — with a hyphen and between its syllables (Wohn-zim-mer, Licht-schacht), never after a single letter and never inside a number. Shortening comes last of all. Preview, PDF and Excel workbook show the same lines — what stands on two lines on screen does so in the printout and in the workbook as well.
  • On the strip sheet the same holds for the cable column: the row lines end before it, the cable stands as a block across its rows, and the name fills that block — it is set as large as the block carries it (at most the medium type of the sheet template) instead of standing small in much white. There too it wraps before it shrinks. Read sideways the lines stand next to each other — the first one left, the second to its right. The column is narrow, so it stops at two lines (zeilen_kabel in the sheet template); if that does not suffice, the type gets smaller. If the name does not go into two lines even at the smallest size, it gets a third — a name on three lines can be read, a cut one cannot. Only after that is it shortened.

9   Output

WayWhat comes out
File ▸ Export ▸ As PDF… (Ctrl+E)Cover sheet, frame layout and one sheet per strip — the required format. Single kinds of sheet can be left out.
File ▸ Export ▸ As Excel workbook…At the front the same sheets in the sheet layout, behind them the data as a table: data per wire, cables per strip, project data — filterable and sortable.
File ▸ Export ▸ As CSV…Plain data: one row per wire at the top, the cables and the project data below.

Which sheets go into the PDF a small dialog asks before saving: cover sheet, frame layout and strip sheets, each with the number of its sheets behind it. Whatever is unchecked is missing from the PDF — cover sheet and frame layout, say, when only the strip sheets are to be printed anew. The sheets in the PDF are numbered consecutively: without a cover sheet the frame layout starts at sheet 1. Without a single check mark Next… is off. The choice is preset the next time; Excel workbook and CSV still carry everything.

The Excel workbook takes over the order and width of the columns, the font sizes, the row heights, the merged cable block including its rotation and the setup for A4. The title block looks like the one on the sheet as well: the same framed block in the arrangement of the sheet template — with schriftfeld_art: beispiel the matrix of date and name at the top left, frame, number and strip at the bottom left, the two addresses in boxes of their own on the right. The frame layout carries it too, and the cover sheet lists the same rows as the printed one.

The pages are filled just as in the PDF: row heights, cell sizes and the air between them come from the sheet model, the bays of the frame layout stand side by side, and from three bays on each one gets a sheet of its own — exactly as when printing. Printing puts each sheet on one page in width and height.

The title block stands at the foot of the sheet as it does on the printed one: the free area lies above it, not below.

The CSV carries the same — only without the sheet layout. A CSV knows one table only, so the others stand below it as blocks, separated by an empty line and with a heading of their own: Kabel je Leiste (cables per strip) and Projektdaten (project data). The assignment stays at the top so that the first line is the header row and every program can read the file as before; the project data come last, just as the title block stands at the foot of the sheet. A multi-line address is kept in one line, separated by „·".

All the same, the workbook cannot imitate a PDF: Excel is a grid, the sheet a drawing — the cable block is merged across its rows instead of drawn freely.

10   Files, folders and backup

WhatWhere
Project filewherever you save it, .vtly
Working folderWindows: daten\ next to the program. Linux: ~/.config/Verteilerly
SettingsVerteilerly.conf — one file, never the registry

In the working folder lie vorlagen/ (templates), blattvorlagen/ (sheet templates) and kabeltypen/ (cable types) as YAML. What is missing the program puts there at startup. A supplied file is only refreshed if it still lies exactly as it was put there — your own changes stay untouched.

Checking templates before they go into the program — the menu Tools carries one entry per kind of template: Check frame template…, Check sheet template… and Check cable types…. Each opens a YAML file — anywhere on the disk, it need not lie in the working folder yet — and reports on it:

  • whether the program can read the file, and if not, what is wrong;
  • what it has read in it: identifier, name, columns, title block, measures. That shows whether the file is understood the way it was meant;
  • remarks — keys the program does not know, and for a sheet template a file name that does not carry its identifier;
  • to be refreshed — entries that no longer exist in this form. They are skipped while reading, and the report names them together with the version in which they went.

Refreshing — if something stands under to be refreshed, the report carries a button Refresh…. It rewrites the file to today's state: the collective mark eigene is replaced by the names of the own fields, zeilen_kabel moves out of the block belegung to sheet level. Only what the program knows as retired is changed — an unknown key stays, because it may be a typo. Comments and the order of the lines are lost in the process, since the file is written anew; the old version stays next to it as <name>.yaml.alt. Before writing, the program reads the result once more as in operation — what would fail there is not written.

It is read by the same rules as at startup: what the report approves, the program accepts as well. Only then put the file into the working folder and restart.

Managing templates — Settings ▸ Frame templates… (Ctrl+Shift+V) renames a template or deletes it, a supplied one as well: whoever never needs one should not have it in the menu with every new frame. What is renamed is the name, not the identifier — that is the file name. Deleted supplied templates stay deleted, even after a restart; the button Restore supplied templates brings them back exactly as they were delivered — changed ones as well. Your own templates stay untouched by it.

A frame template is a file in vorlagen/. The even frame needs three numbers:

id: 40da-4x10
name: "40 DA - 4 Leisten zu 10 DA"
beschreibung: "Vier Leisten in einer Bucht, je 10 Doppeladern."
buchten: 1
leisten_je_bucht: 4
da_je_leiste: 10

An unevenly equipped one carries a list under buchten — one row per bay — instead of the number:

id: bunter-keller
name: "Bunter Keller"
buchten:
  - {leisten: 4, da: 10}
  - {leisten: 2, da: 20}
  - {leisten: 6, da: 8}

The program writes both itself when you choose Save as template in the dialog; created by hand it is read just the same. A new file in the folder is offered at the next start without anything having to be changed in the program.

Language — Settings ▸ Language switches the interface to Deutsch or English: menus, dialogs, buttons, hints and messages. The choice applies after a restart — the menus are labeled once when the window is built. It belongs to the workplace and is kept in the Verteilerly.conf.

The sheets are not switched over with it: what is on them is your document and not a program interface — the words of the title block can be changed per project anyway (Advanced: change the wording on the sheet). The names of the supplied templates stay German as well: they are data in the working folder, and you may rename them.

In the Verteilerly.conf are the sheet template, the language, the notation of the jumpers, the free-text switch, the appearance, the remembered project data and the default for how new frames label their strips. What concerns the single frame is in the project file instead.

If the file cannot be read — it is half written, locked, or lies in a place the program may not read —, then it is left untouched: the program says so at startup and works with throw-away settings for that run. So it does not write defaults over your values. Take a look at the file then and put it aside if need be; it will be created anew on the next start.

Backup and restore — Settings ▸ Back up templates and settings… packs frame templates, sheet templates, cable types and the settings into a ZIP file; … restore… brings them back. In both directions check marks choose what comes along, and the dialog shows beforehand what is in the package. On restoring, only the known subfolders and only YAML are taken over — a package from someone else cannot create anything outside the working folder. Which extensions are switched on does not come with a package: each computer decides that for itself.

11   Extensions

The Extensions menu carries what goes beyond the core of the program. Built in so far is the sheet template editor; extensions of your own can be added.

11.1   The sheet template editor

Extensions ▸ Sheet template editor… shows the values of a sheet template on the left and a sheet on the right, drawn exactly like the preview and the PDF. At the top is the template — at first the one currently chosen, any other can be fetched there; below it its name and its description, both editable. Every change shows on the sheet after a moment: margin, header, title block and row heights, the four font sizes, the measurements of the frame layout including the cable block, the switches for pair numbers and the cable name turned across, and the columns of the strip sheet — field, heading, share of the width and alignment, with Add, Remove, Up and Down. The editor window can be resized and maximized — the bigger it is, the more of the sheet is visible. Above the sheet you choose which one is shown; shown is the open frame, otherwise an example.

Whatever the program would reject when reading a template file appears as a red sentence below the sheet, and then it cannot be saved — an empty name belongs to that as well. There are two ways to save:

  • Save writes the changes back into the file of the loaded template: this is how an existing one is edited. The button is only to be had if it has a file in the working folder (blattvorlagen/) — the built-in default stands in the program and cannot be overwritten. A supplied template can be changed this way too; it is then no longer refreshed, and Tools ▸ Restore supplied templates brings it back if need be.
  • Save as new template… asks for a name and creates a new file; with the same name it gets a number appended. An existing template is never overwritten in the process.
  • Reset (on the left of the button row) brings the loaded template back — every change is dropped, and it asks first. What is meant is the state in the file, so after a save the saved one. As long as nothing is changed, the button is off.

The file only holds what differs from the built-in default, like a hand-written one (section 7.1). A template is chosen like any other under Settings ▸ Sheet template. Where no frame is open, the example carries project data, so that the title block shows values as well.

The letterhead — the title block at the foot of the sheet — has a group of its own: the height, below it the blocks side by side as on the sheet, each with its entries one below the other (company, customer, frame, sheet, created, custom fields …). Entries can be dragged between the blocks; + adds an entry — among them the horizontal rule, which draws a line in the block —, − removes the chosen entry and ✕ deletes that very block. Behind every entry stands a button for its alignment — left, centered or right; it applies to the value, not to the label. The horizontal rule has none: it is a line and has nothing to align. Add block and Remove last block change the number of blocks; one always remains. With Set the widths myself every block gets its share of the width, otherwise the program divides by eye.

The kind stands above the height and decides where the title block comes from: Blocks is built by the editor itself — the normal case —, Like the sample tables takes the fixed title block of the ODS templates (schriftfeld_art: beispiel): the matrix of date and name at the top left, the frame below it, company and customer as two boxes on the right. That arrangement lives in the program, not in the template; the block list is then locked and says so. The height and the left half remain adjustable — its share of the width, the rest belongs to the addresses (schriftfeld_anteile). Switching works both ways, and whatever is not drawn stays in the file: the blocks survive a trip to the sample tables.

The group Own fields below it creates the freely named rows of the title block: Add puts a new one into the list (the name is typed right away), Remove takes the selected one out, Up and Down order them. They become visible through the mark eigene in the the + menu of the title block: there the own fields stand behind the fixed entries, after a separator, and each one is put into the block where it belongs — so several fields can be distributed independently. The check mark row Show on says on which kinds of sheet they appear. Only the names stand here — the rows are filled in per frame under Edit ▸ Project data. If a field is renamed or removed, its entry disappears from the title block with it: it would otherwise point at nothing.

11.2   The log

Extensions ▸ Log… shows what the program reported last. Everything that otherwise only appears briefly in the status bar is lost when the program ends, and an unexpected error vanishes entirely in the Windows version: it has no console on which a report could appear. The built-in extension Log therefore writes both into the file Verteilerly.log in the working folder:

  • Events — every message of the status bar, with its time. Each run begins with four lines: version, Python and Qt; the path of the running program; the Verteilerly.conf in use together with the number of values in it; and the invocation with the working directory. Whoever reads a report later knows not only which build produced it, but also where this run took its settings from — two starts by different routes (by hand, by a double click on a project file) can be compared that way.
  • Unexpected errors — whatever no part of the program caught lands in the file together with its report. The user gets a window with the sentence and the path to the log; the program keeps running.

The dialog shows the content with the newest at the bottom. Refresh reads the file again — it grows while the dialog is open —, Open folder shows it in the file manager, Clear the log throws away what has accumulated. The file stays small: beyond 200,000 characters the older half falls away, and a line says that it was cut.

The log is an addition, not a part of operation: if it cannot be written — a full disk, missing rights —, the program carries on, and the reason stands in the dialog. It does not travel in a package (Back up templates and settings); it belongs to this machine. Whoever wants no log at all switches the extension off under Manage extensions.

11.3   Managing extensions

Extensions ▸ Manage extensions… lists every extension found with a check mark, its version, its origin and description — or the reason why it could not be loaded. Built-in ones are switched on, your own ones only once you switch them on. The choice applies from the next start and is kept in the Verteilerly.conf.

As long as the check mark Load only bundled extensions is set — and it is by default — all of your own extensions stay off, even switched-on ones. Their check marks in the list are greyed out but kept. To use your own extensions, remove this check mark and switch on the ones you want.

A built-in extension is shipped with the program and therefore carries its version — the date of the release, year.month.day, with b2, b3 … appended for several builds on one day. One of your own counts however it likes: what stands in the column is its own statement. If it names none, a dash stands there.

11.4   Writing an extension of your own

An extension is a Python file — or a folder with __init__.py — in the erweiterungen folder of the working folder; Manage extensions names it and opens it at the press of a button. An extension of your own is program code and runs with all the rights of Verteilerly. That is why it is only executed once it is switched on; until then the program only reads the first line of its docstring and its version. It can use everything the program carries — Qt through PySide6, YAML, ReportLab, openpyxl and the modules of Verteilerly —, but no further libraries.

"""Hello: says hello in the status bar."""
from verteilerly.erweiterungen import Erweiterung


class Hallo(Erweiterung):
    kennung = "hallo"
    name = "Hello"
    beschreibung = "Says hello in the status bar"
    version = "1.0"

    def einrichten(self, programm):
        programm.menueeintrag("Say hello",
                              lambda: programm.meldung("Hello!"))


erweiterung = Hallo()

kennung is the name in the Verteilerly.conf and must be unique; name and beschreibung stand in Manage extensions. version is optional and may count however you like — 1.0, 2026-09-20, v3-beta. Like the docstring it is read without executing the file; for that it may just as well stand next to the class as version = "1.0" or __version__ = "1.0".

The object erweiterung is what the program looks for. In einrichten() it gets the interface programm:

CallWhat it does
menueeintrag(text, aufruf, hinweis, kuerzel)An entry in the Extensions menu. An error in the call is shown instead of stopping the program.
projekt()The open frame including the project data — or None.
blattvorlagen(), blattvorlage()All sheet templates and the one currently chosen.
blattvorlagen_neu_laden()Reads the sheet templates anew.
blattvorlagenordner()Where your own sheet templates are written.
meldung(text)A sentence in the status bar.
farben()The color set of the appearance.
fensterThe main window, for instance as the parent of a dialog of your own.

If an extension cannot be loaded or set up, it is skipped, and the program says at start what went wrong. If an extension of your own prevents the start, calling the program with --ohne-fremde-erweiterungen helps: then it loads none of your own, and it can be switched off under Manage extensions.

13   Information about the program

Is there anything newer? — Settings ▸ Look for updates once a day. With the check mark set, Verteilerly asks the project's public release list once a day and says so in the status bar if a newer version is there — with the address where to get it. Nothing is downloaded, and nothing is sent beyond the request itself. The look happens alongside the program: it does not hold up the start, and without a network it stays silent.

Look right now — Help ▸ Look for updates… asks straight away, regardless of the check mark, and says in every case what came of it: that a newer version is out (with its address), that this one is the newest, or that the list could not be reached — then the internet connection is worth a look.

Without the check mark the program never goes online. Only the day of the last look is remembered (in Verteilerly.conf), so that it really stays at once a day. Verification uses the certificate store of the machine; where none is found, the look is skipped — Verteilerly brings no root certificates of its own, they would only go stale.

Help ▸ Documentation (F1) opens this page: on the left the table of contents, on the right the text.

Searching. Above the text is a search field (Ctrl+F). The search runs as you type, from the second character on; upper and lower case make no difference. Every match is highlighted, the one currently aimed at strongly, the others faintly, and on the right stands which of how many it is. Enter, F3 or the arrow › go to the next one, Shift+F3 and ‹ to the previous one — at the end it starts over. It begins at the place that is currently visible: whoever is reading the section about cables means the next match from there. Esc clears the search away; pressed again, it closes the window.

Help ▸ About Verteilerly lists every component with version, license and task — Python, PySide6, Qt, ReportLab, openpyxl, PyYAML —, together with system, working folder, settings file and the folder with the licenses. The versions come from the running program, not from a maintained list.

The complete license texts stand in the about window as links — GNU GPL, GNU LGPL and the Qt source code. Besides that they are put into the working folder at the first start (lizenzen/, with QUELLEN.txt, which says for every component where its source code comes from): that way they can be read without a network as well and stay there when the program has ended. They are in the AppImage itself too, but there in the mount point, which the operating system clears away when the program ends.
